# Интеллектуальный ассистент для «1С:УНФ 3.0» (Омниканальная платформа на базе ИИ)

> **Проект Всероссийского конкурса дипломных проектов фирмы «1С»**  
> **Номинация:** «Лучший инновационный проект с использованием передовых технологий (ИИ/Интеграции)»  
> **Режимы работы:** облачный LLM-клиент и локальная классификация поддерживаемых запросов по правилам. Ветви подключения отечественных моделей предусмотрены в коде; совместимость с конкретным провайдером требует отдельной проверки.

---

## ⚡ Экспресс-запуск стенда в 1 клик

Для демонстрации предусмотрен изолированный офлайн-запуск (требуются Python 3.12 и установленные зависимости):

1. **Запустите файл [`run_demo.bat`](run_demo.bat) (двойной клик под Windows)**.

3. Подробная инструкция со сценариями: **[`docs/contest/QUICKSTART_CONTEST.md`](docs/contest/QUICKSTART_CONTEST.md)**.
4. Паспорт проекта для оргкомитета: **[`docs/contest/CONTEST_PROJECT_PASSPORT.md`](docs/contest/CONTEST_PROJECT_PASSPORT.md)**.

## 🏛️ Ключевые возможности и архитектура

### 1. Интеграция с «1С:Предприятие 8.3 / 8.5»
* **Конфигурация на замке**: Внедрение через расширения CFE без изменения типовой конфигурации.
* **Белый список действий (Action Whitelist)**: Нейросеть не имеет прямого доступа к базе данных — все операции выполняются через типизированный диспетчер BSL.
* **Готовая демо-база**: Файл `archive/dumps/Diplom_28.05.dt` с наполненными справочниками, остатками и заказами.

### 2. Прикладные бизнес-модули РФ
* **115-ФЗ Комплаенс**: Экспресс-проверка контрагентов (алгоритм контрольных сумм ИНН, стоп-факторы) и скоринг платежей.
* **Защита маржинальности**: Контроль наценки с авто-маршрутизацией запросов на согласование скидок в Канбан.
* **Работа с задолженностью**: учебный расчёт процентов и подготовка претензии с возможностью почтовой отправки. Встроенная таблица ставок и налоговые допущения требуют сверки с первичными источниками перед практическим применением; результат не является юридическим заключением.
* **Умный автозаказ ROP/EOQ**: Формула Уилсона + неснижаемые остатки с генерацией черновика `ЗаказПоставщику`.
* **Разбор текста накладных**: извлечение реквизитов и строк из `raw_text`, проверка арифметики и нечёткое сопоставление номенклатуры. Распознавание изображений в текущем сервисе отключено.

### 3. Омниканальность (Единое окно)
* **Веб-интерфейс middleware**: пульты управления бизнес-модулями, финансовый монитор и чат. Это отдельное приложение, связанное с 1С.
* **Telegram-бот (@qelildiplom_bot)**: Голосовое управление (Whisper/SpeechKit), инлайн-кнопки, команды `/gap`, `/balance`, `/debts`, `/orders`.
* **ВКонтакте**: Российский чат-бот для складского персонала и экспедиторов.
* **Корпоративная почта**: Робот Email-to-Order и рассылка утренних дайджестов руководителю.

### 4. Отечественный стек ИИ и импортозамещение
* В коде предусмотрены настройки GigaChat, YandexGPT и OpenAI-совместимого локального сервера. Наличие настроек не доказывает успешную авторизацию, обновление токена или совместимость API: необходим отдельный интеграционный прогон.
* Текущее хранилище middleware — SQLite с настройкой WAL. Postgres Pro, Astra Linux и РЕД ОС рассматриваются как направления развития; их развёртывание и совместимость в этом аудите не подтверждены. Локальное выполнение само по себе не доказывает соответствие 152-ФЗ.

## Основные возможности

- консультации по методологии работы в 1С:УНФ;
- поиск и открытие объектов, подготовка документов и запуск прикладных действий в 1С;
- запрос остатков, статусов, должников и аналитики;
- создание канбан-задач из чата;
- канбан-доска с фильтрацией, статистикой, уведомлениями, экспортом CSV и обменом с 1С;
- загрузка метаданных конфигурации и добавление релевантных объектов в контекст LLM;
- JWT-авторизация и роли `admin`, `manager`, `employee`.

## Проверка

Рабочая команда запуска тестов:

```powershell
cd Middleware
.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider
```

Результат проверки определяется итогом полного запуска pytest. Изоляция тестов описана в [руководстве middleware](Middleware/README.md#изолированный-запуск-тестов). Внутрипроцессные API-тесты проверяют контракт middleware, но не загрузку расширения и работу в живой базе 1С.

Проверка исходников 10.09.2026: `142 passed in 139.50s`. Структурный валидатор расширения прошёл 13 проверок; CFE собран платформой 1С 8.5.1.1302. Проверка чистого офлайн-профиля прошла. CI-сценарий добавлен, но запуск на GitHub и живые сценарии УНФ не подтверждены. DOCX/PPTX отложены для отдельной работы; технический комплект собирается через `scripts/package_contest.py`.

## Важные особенности конфигурации стенда

- Синтетические демонстрационные учётные записи имеют известные пароли (`director/director123`, `cfo/cfo123`, `accountant/buh123`, `manager/manager123`, `admin/admin`). Они небезопасны для промышленной среды.
- Обмен между 1С и middleware по умолчанию настроен на локальный HTTP `127.0.0.1:8000`.
- Лексический RAG работает по загруженным метаданным. Чистый профиль не содержит индекса конкретной базы; локальная классификация поддерживаемых запросов доступна без него.
- `release/` и `dist/` формируются из технических исходников. Текст диплома и презентация отложены для отдельной подготовки.
- Уровни проверки и остаточные ограничения перечислены в [чек-листе](docs/contest/CONTEST_CHECKLIST_AND_PACKAGE.md).
