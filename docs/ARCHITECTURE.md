# Архитектура решения

Документ описывает фактическую архитектуру проекта на 30 августа 2026 года. Источниками истины являются `Middleware/main.py`, сервисы в `Middleware/app/services/` и модули в `1c_extensions/`.

## 1. Назначение

Решение добавляет в 1С:УНФ два пользовательских интерфейса:

1. чат интеллектуального ассистента, который консультирует и возвращает формализованную команду;
2. канбан-доску для постановки и контроля задач.

Middleware отделяет интерфейс и прикладные операции 1С от внешней LLM, авторизации и хранения задач. Команды, требующие работы с объектами УНФ, исполняются на стороне 1С; middleware не подключается напрямую к информационной базе 1С.

## 2. Компоненты

### 2.1. Расширение «ИнтеллектуальныйАссистент»

Основной модуль — `1c_extensions/1C_Full_Code_v6.bsl`.

Он отвечает за HTML-интерфейс чата, историю сообщений, отправку контекста в `/chat`, обработку ответа и выполнение разрешённых действий средствами платформы 1С. В модуле также реализованы загрузка метаданных в `/update_metadata`, создание канбан-задачи и быстрые кнопки «Заказы», «Канбан», «Сегодня», «Должники», «Клиенты».

LLM не исполняет BSL-код и не получает произвольный доступ к платформе. Она возвращает JSON с полями `text`, `action` и `data`; модуль формы сопоставляет `action` с заранее реализованной веткой.

### 2.2. Расширение «КанбанДоска»

- `1c_extensions/1C_Kanban_Extension.bsl` — desktop-форма с HTML-доской;
- `1c_extensions/1C_Kanban_Mobile.bsl` — упрощённая мобильная форма;
- `1c_extensions/1C_Shared_HTTP.bsl` — эталонный общий фрагмент HTTP/JWT-обмена, продублированный в актуальных модулях форм для автономной установки.

Обе формы получают JWT через `/auth/login`, передают его в `X-Auth-Token` и вызывают API задач.

### 2.3. FastAPI middleware

Точка входа — `Middleware/main.py`. В одном процессе инициализируются четыре сервиса:

| Сервис | Ответственность |
|---|---|
| `AuthService` | пользователи, подразделения, bcrypt, JWT, роли |
| `LLMService` | выбор провайдера, системный prompt, вызов модели, разбор и проверка JSON |
| `MetadataService` | загрузка индекса, RAG-поиск и обновление метаданных |
| `KanbanService` | CRUD задач, видимость по ролям, статистика, CSV и синхронизация |

FastAPI также предоставляет CORS, журналирование метода/пути, health-check и ограничение частоты запросов. Общий лимит — 60 запросов в минуту; для входа — 5, для чата — 30. Ограничение можно отключить через `RATE_LIMIT_ENABLED=false`.

### 2.4. Хранилища

`Middleware/kanban.db` — SQLite-база с тремя таблицами: `users`, `departments`, `kanban_tasks`. Таблицы создаются при импорте сервисов. Если таблица пользователей пуста, добавляются демонстрационные подразделения и учётные записи.

RAG использует:

- `metadata_index_lite.json` — облегчённое описание объектов и полей;
- `metadata_embeddings.npy` — предвычисленные векторы, если файл присутствует (в текущем корневом комплекте отсутствует);
- `metadata_store.json` — полный набор, полученный через `/update_metadata`.

Пути к этим файлам в текущем `MetadataService` относительны рабочему каталогу. Поэтому middleware следует запускать из каталога `Middleware`.

## 3. Основные потоки

### 3.1. Авторизация 1С

```text
Форма 1С → POST /auth/login → проверка bcrypt → JWT
Форма 1С ← access_token
Форма 1С → запрос с X-Auth-Token → проверка JWT и активности пользователя
```

При ответе 401 BSL-обёртка повторно получает токен и повторяет исходный запрос.

### 3.2. Диалог с ассистентом

```text
Сообщение + история + контекст формы 1С
  → POST /chat
  → RAG: 7 наиболее близких объектов метаданных
  → system prompt + последние 10 сообщений
  → Fireworks или OpenRouter
  → извлечение JSON и whitelist action
  → опциональное создание задачи в SQLite
  → ответ форме 1С
  → выполнение разрешённой команды средствами 1С
```

Если модель возвращает неизвестное действие, middleware заменяет его на `expert_answer`. Для некоторых запросов канбана применяется дополнительная постобработка намерения.

### 3.3. Обновление метаданных

Администратор инициирует сбор метаданных в форме чата. 1С перечисляет поддерживаемые объекты и их поля, затем отправляет массив в `POST /update_metadata`. Middleware записывает полный индекс и, если доступна ML-модель, пересчитывает embeddings.

### 3.4. Работа с канбаном

Форма 1С обращается к `/kanban/tasks` и `/kanban/tasks/move`. Чат может вернуть `create_kanban_task`; в этом случае middleware создаёт задачу с источником `chat` ещё до отправки ответа в 1С.

Видимость зависит от роли:

| Роль | Видимость задач |
|---|---|
| `admin` | все задачи; доступен фильтр подразделения |
| `manager` | подразделение менеджера, назначенные и созданные им задачи |
| `employee` | назначенные сотруднику или созданные им задачи |

## 4. Контракт действий ассистента

Middleware допускает 17 значений `action`:

`expert_answer`, `create_object`, `open_list`, `open_form`, `find_object`, `prepare_payment`, `accrual_writeoff`, `warehouse_move`, `employee_info`, `get_dossier`, `get_status`, `get_stock`, `get_debtors`, `run_analytics`, `create_kanban_task`, `show_kanban`, `update_metadata`.

В `1C_Full_Code_v6.bsl` есть ветки исполнения для всех этих действий. `expert_answer` выводит консультацию без прикладного действия; `create_kanban_task` исполняется middleware и затем отображается в 1С.

## 5. Конфигурация

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `FIREWORKS_API_KEY` | ключ Fireworks; имеет приоритет | не задан |
| `OPENROUTER_API_KEY` | резервный ключ OpenRouter | не задан |
| `JWT_SECRET` | подпись JWT | случайный на каждый процесс, если не задан |
| `JWT_ALGORITHM` | алгоритм JWT | `HS256` |
| `JWT_EXPIRE_HOURS` | срок действия токена | `24` |
| `MIDDLEWARE_HOST` | адрес прослушивания | `0.0.0.0` в `main.py` |
| `MIDDLEWARE_PORT` | порт | `8000` |
| `LOG_LEVEL` | уровень журнала | `INFO` |
| `CORS_ORIGINS` | разрешённые origins через запятую | localhost:3000 и localhost:8000 |
| `RATE_LIMIT_ENABLED` | включение rate limit | `true` |

При наличии обоих LLM-ключей выбирается Fireworks. Поле `temperature` в запросе `/chat` сейчас не влияет на вызов: сервис использует фиксированное значение `0.3`.

## 6. Границы и технический долг

- Встроенные демонстрационные пароли и сервисная роль администратора допустимы только для локального стенда.
- HTTP-адрес и порт по умолчанию зашиты в BSL; для удалённого сервера нужны параметры формы и HTTPS.
- Два сервиса создают отдельные SQLAlchemy engine для одного SQLite-файла; миграций схемы нет.
- Docker volume `/app/data` не совпадает с текущими путями БД и RAG-файлов.
- В `find_top_matches()` проверка `embeddings is None` выполняется до перехода к лексическому fallback. Поэтому без ML-модели и файла embeddings RAG сейчас не возвращает кандидатов; это дефект, а не штатный fallback-режим.
- `release/` — копия артефактов, а не автоматически воспроизводимая сборка.
- BSL-модули покрыты контрактными Python-тестами, но требуют ручной компиляции и сценарной проверки в 1С.
