# Структура проекта и актуальные артефакты

Репозиторий содержит одновременно исходный код, рабочий текст диплома, выгрузки 1С и снимок демонстрационного релиза. Этот документ определяет, какие файлы являются исходниками, а какие — производными материалами.

## 1. Исходный код решения

```text
Middleware/
├── main.py                     FastAPI и REST-маршруты
├── app/
│   ├── models/                 Pydantic-контракты API
│   └── services/
│       ├── auth_service.py     JWT, пользователи, подразделения
│       ├── kanban_service.py   SQLite и логика канбана
│       ├── llm_service.py      LLM, prompt и whitelist действий
│       └── metadata_service.py RAG-индекс и поиск
├── tests/                      46 автоматических тестов
├── requirements.txt           локальная разработка и тестирование
├── requirements-server.txt    облегчённый Docker-профиль
├── Dockerfile
└── .env.example

1c_extensions/
├── 1C_Full_Code_v6.bsl        форма чат-ассистента
├── 1C_Kanban_Extension.bsl    desktop-канбан
├── 1C_Kanban_Mobile.bsl       мобильный канбан
├── 1C_Shared_HTTP.bsl         общий образец HTTP/JWT-функций
└── 1C_Full_Code_v6_outline.md сокращённое описание модуля для приложения диплома
```

Изменения функций следует вносить в корневые `Middleware/` и `1c_extensions/`. Копии в `release/` не являются источником истины.

## 2. Текст диплома

Актуальный набор исходных глав:

1. `text/00_Введение_рерайт.md`;
2. `text/01_Глава1_Аналитика_рерайт.md`;
3. `text/02_Глава2_Проектирование_рерайт.md`;
4. `text/03_Глава3_Реализация_рерайт.md`;
5. `text/04_Глава4_БЖД_рерайт.md`;
6. `text/05_Заключение_Источники_Приложения_рерайт.md`.

`assemble_diploma.py` объединяет их в `text/Диплом_ИИ_ассистент_1С_полный_рерайт.md` и подставляет сокращённый листинг 1С. `text/build_docx_final.py` формирует итоговый DOCX с рисунками из `text/figures/`.

Файлы без `_рерайт`, `.bak`, `.bak2`, `.bak3` и `figures_backup/` — предыдущие версии или резервные копии. Их нельзя использовать как основу конкурсной редакции без явного сравнения.

Дополнительные материалы:

- `text/Аннотация.md` — аннотация;
- `text/Речь_для_защиты.md` — сценарий выступления;
- `text/diagram_specs/` — задания и Mermaid-коды для рисунков;
- `text/Диплом_ИИ_ассистент_1С_окончательный.docx` — последняя локальная сборка, но воспроизводимым источником остаются Markdown-главы.

## 3. Артефакты 1С

| Артефакт | Назначение | Комментарий |
|---|---|---|
| `Diplom_28.05.dt` | выгрузка информационной базы | крупный бинарный снимок, игнорируется Git |
| `unpack_me.cf` | выгрузка конфигурации | крупный бинарный снимок |
| `config_unpacked/` | XML-выгрузка конфигурации УНФ | нужна для анализа метаданных, не редактируется вручную |
| `src/` | результаты экспериментов по распаковке DT/CF | содержит временные копии и журналы |
| `unpack_config.py` | автоматизация выгрузки CF в XML | требует установленной платформы 1С |

`config_unpacked/` — полная конфигурация УНФ, а не только доработка диплома. При анализе авторского вклада следует отделять её от файлов расширений.

## 4. Релиз

`release/` содержит автономный демонстрационный комплект: базу `1Cv8.dt`, презентацию, исходники расширений, middleware, документацию и итоговые материалы диплома.

Каталог собран копированием и уже содержит служебные файлы (`.env`, SQLite, `__pycache__`, журналы). Перед конкурсной публикацией его необходимо пересобрать из корневых исходников, удалить секреты и кэши, сменить демонстрационные пароли и проверить комплект на чистой машине.

## 6. Что не следует коммитить или публиковать

- `Middleware/.env` и любые реальные API-ключи;
- `*.db` с пользовательскими данными;
- `__pycache__`, тестовые кэши и журналы;
- `metadata_embeddings.npy`, если лицензия/размер комплекта не предполагают его распространение;
- крупные `*.dt` и промежуточные архивы без явной необходимости;
- резервные копии текста и дубли с неясной актуальностью.

## 7. Рекомендуемый цикл изменения

1. Изменить корневой исходный код или одну из шести глав `_рерайт`.
2. Запустить тесты middleware и ручную проверку BSL в 1С.
3. Обновить техническую документацию и главы, если изменился контракт решения.
4. Выполнить `python assemble_diploma.py`.
5. Собрать DOCX через `text/build_docx_final.py`.
6. Пересобрать чистый `release/` и провести установку на отдельном стенде.
