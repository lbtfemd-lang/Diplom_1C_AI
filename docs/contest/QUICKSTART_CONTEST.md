# Запуск технического демо

Требуются Windows, Python 3.12 и зависимости из Middleware/requirements.txt. Установка зависимостей требует доступа к источнику пакетов; длительность установки не гарантируется.

## Подготовка

Из корня проекта:

```powershell
py -3.12 -m venv Middleware/.venv
./Middleware/.venv/Scripts/python.exe -m pip install -r Middleware/requirements.txt
./run_demo.bat --check
./run_demo.bat
```

Если исправное окружение уже существует, создание и установка не нужны. Лончер не удаляет окружение и не устанавливает зависимости автоматически.

Откройте http://127.0.0.1:8000. Демо использует свежую временную SQLite, случайный JWT-секрет и синтетических пользователей. Рабочие .env, БД и индекс метаданных не читаются. Внешние соединения запрещены; исходящая почта и реальные мессенджеры не демонстрируются. После остановки процесса демо-данные удаляются.

## Синтетические пользователи

| Роль | Логин | Демонстрационный пароль |
|---|---|---|
| Директор | director | director123 |
| Финансовый директор | cfo | cfo123 |
| Менеджер | manager | manager123 |
| Склад | warehouse | warehouse123 |
| Сотрудник | employee | employee123 |
| Администратор | admin | admin |

Эти открыто известные пароли небезопасны для промышленной среды. В рабочем режиме существующие роли не сбрасываются при старте.

## Репетиция

1. Войти сотрудником; запрос «Какой кассовый разрыв?» должен вернуть отказ.
2. Создать собственную задачу, переместить её. Чужие задачи не должны появиться в списке, статистике, уведомлениях или CSV.
3. Войти директором; повторить финансовый запрос. Веб-монитор использует демонстрационные данные до отдельной синхронизации с 1С.
4. Показать калькулятор запасов: ROP/EOQ и черновик заказа. Это ещё не документ, записанный или проведённый в УНФ.
5. Показать расчёт маржи и задолженности. Налоговые ставки и локальная таблица ставок — учебные допущения, не актуальный нормативный справочник.
6. Показать разбор текстового счёта. Обработка скана без извлечённого текста не подтверждена.
7. Завершить сервер Ctrl+C. Повторный запуск создаёт чистый профиль.

## Контур 1С

### Доступ сотрудников к ассистенту

Ручная проверка сотрудником подтвердила вход и открытие чата. Канбан пока не принят: запрос к Задача.ЗадачаИсполнителя получает отказ доступа. Для разграничения отсутствующего права чтения и ограничения отдельных записей откройте типовой список «Мои задачи» под тем же сотрудником. В текущей базе подтверждены роли «Чтение задач» и «Изменение и выполнение задач» с ограничениями доступа к записям. Не заменяйте их безусловными правами расширения; успешное открытие чата не доказывает доступ к задачам.

В SmallBusinessDemo установлена отдельная роль `ИА_ИспользованиеАссистента` с синонимом «Использование ИИ-ассистента». Она содержит 7 разрешений: просмотр подсистемы и двух команд, использование и просмотр двух обработок. Права на задачи, справочники и документы предоставляют существующие профили УНФ. Роль не добавлена в DefaultRoles и автоматически сотрудникам не назначалась.

В новом сеансе администратора откройте настройки пользователей и прав, затем профили групп доступа. Создайте отдельный профиль «Использование ИИ-ассистента» и включите в него только одноимённую роль (поиск также по техническому имени). Создайте группу доступа с этим профилем и включите проверяемого сотрудника, сохранив его прежние группы. Если роль не видна в списке доступных ролей профиля, остановитесь и зафиксируйте это: интеграция новой роли с интерфейсом профилей БСП ещё не проверена. Не заменяйте её полными правами и не редактируйте типовой профиль «Продажи».

После назначения завершите старый сеанс сотрудника и войдите снова. Проверьте появление раздела «ИИ Ассистент», открытие чата и канбана, создание собственной тестовой задачи. Ошибки доступа к данным фиксируйте отдельно — роль ассистента не должна расширять существующие ограничения УНФ. Личная роль middleware проверяется независимо.

CFE собирается из 1c_extensions/ai_assistant_src через scripts/build_extension.py. Общий BSL-листинг чата совпадает с модулем в XML-выгрузке. Для привилегированных запросов нужен личный JWT. Проверка исходников 10.09.2026 обнаружила, что поля ЛогинMiddleware и ПарольMiddleware скрыты, а обработчик настроек предлагает только адрес сервера. Поэтому пользовательский сценарий личного входа из формы пока не подтверждён. Сервисный вход не повышает роль по имени пользователя 1С; вход директором в УНФ сам по себе не даёт роли director в middleware.

Установка CFE и выполнение сценария в целевой УНФ требуют отдельной проверки выбранной базы. Архив не содержит локальную информационную базу, старые EPF или индекс её метаданных. Не восстанавливайте исторический дамп поверх рабочей базы.

Текст диплома и презентация будут подготовлены отдельно. Текущий состав и ограничения — [чек-лист](CONTEST_CHECKLIST_AND_PACKAGE.md).

## Ручная проверка установленного расширения

Результат ручной проверки последнего исправления: пользователь подтвердил штатное открытие формы, выбор значений, создание и изменение задачи (runtime/live, acceptance). Упоминания ожидания проверки ниже относятся к подготовке сборок. Проверку под ограниченной ролью, отказ без исполнителя и согласование несовместимого заказа отдельно ещё не подтверждали.

Последующее исправление установлено: тип исполнителя берётся из РеквизитыАдресации, открытие задачи выполняется только через Обработка.КанбанДоска.Форма.ФормаЗадачи. При ошибке платформа показывает исходную диагностику; резервная подмена типовой формой удалена. Проверять в новом сеансе через «ИИ Ассистент» → «Канбан-доска» → «Задача (1С)», не через отдельный EPF. Ожидаемый заголовок — «Задача (1С:Предприятие)» и поля темы, контрагента, заказа, исполнителя. Загрузка подтверждена сверкой обоих модулей; живое открытие и сохранение ожидают ручной проверки.

Доработка выбора реквизитов задачи: сборка CFE ограничивает выбор контрагентами, заказами покупателей и типом исполнителя из метаданных ЗадачаИсполнителя. При выборе заказа заполняется его контрагент; смена контрагента сбрасывает несовместимый заказ. Пустой исполнитель блокирует сохранение. Эта сборка загружена и применена в SmallBusinessDemo 10.09.2026; обратная выгрузка совпала с технической по всем 20 файлам (deploy). В новом сеансе проверить выбор каждого поля через кнопку и ввод текста, сохранение и повторное открытие, смену контрагента и очистку связи. Для нативной формы задачи middleware не требуется. Работа выбора в живой форме пока ожидает ручной проверки.

Черновик заказа и действия, изменяющие учётные документы, проверять после доступного личного входа в чате. До этого не обходить авторизацию и не проводить документы ради демонстрации.

Результаты передать в виде `шаг — успешно / ошибка / недоступно`, указав контур (1С или браузер) и пользователя. При ошибке приложить её текст и шаг воспроизведения; токены и пароли не прикладывать. Эти результаты дадут runtime/live evidence; функциональное принятие пользователем фиксируется отдельно.
