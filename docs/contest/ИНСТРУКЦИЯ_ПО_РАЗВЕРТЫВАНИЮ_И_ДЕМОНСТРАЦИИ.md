# РУКОВОДСТВО ПО УСТАНОВКЕ И ДЕМОНСТРАЦИИ ПРОГРАММНОГО КОМПЛЕКСА

**Всероссийский конкурс дипломных проектов с использованием программных продуктов фирмы «1С»**

Паспорт демонстрации:
* номинация: «Лучший инновационный проект с использованием передовых технологий (ИИ/Интеграции)» и «Лучший дипломный проект СПО/ВО»;
* тема проекта: Интеллектуальный ассистент на базе искусственного интеллекта и омниканальной архитектуры для типовой конфигурации «1С:Управление нашей фирмой 3.0»;
* базовая конфигурация: «1С:Управление нашей фирмой», редакция 3.0 (типовая конфигурация находится на полной поддержке вендора, без снятия с замка);
* технологическая платформа: «1С:Предприятие 8.3» (релиз 8.3.24 и выше) или «1С:Предприятие 8.5».

---

## 1. Состав комплекта поставки

В состав комплекта поставки входят следующие компоненты:
1. файл выгрузки демонстрационной информационной базы «1С:УНФ 3.0» с предзаполненным контрольным примером и установленным расширением (`dist/SmallBusinessDemo.dt`, объём 1,24 ГБ);
2. верифицированный архив разработки, включающий исходные коды модулей расширения 1С (BSL/XML), скомпилированное расширение `AIAssistant.cfe`, серверный интеграционный слой `Middleware` (FastAPI), набор автоматических тестов и скрипты запуска (`dist/1C_AI_Assistant_Contest_Package.zip`);
3. реестр и контрольные суммы SHA-256 файлов архива (`dist/PACKAGE_CONTENTS.md`);
4. командный файл автоматизированного развёртывания демонстрационной базы 1С и запуска программного комплекса в один клик (`deploy_1c.bat`).

---

## 2. Системные требования

Для развёртывания и функционирования программного комплекса предъявляются следующие системные требования:
* операционная система: Microsoft Windows 10 / 11 (x64);
* среда исполнения: интерпретатор Python версии 3.12 (с установленным пакетным менеджером `pip`);
* технологическая платформа: «1С:Предприятие 8.3» (не ниже релиза 8.3.24) или «1С:Предприятие 8.5»;
* оперативная память: не менее 8 ГБ;
* свободное дисковое пространство на накопителе: не менее 5 ГБ.

---

## 3. Разграничение контуров аутентификации и учётные записи

В архитектуре системы строго разделены два контура безопасности, функционирующие по принципу наименьших привилегий:

### 3.1. Контур технологической платформы «1С:Предприятие 8.3»

Данные учётные записи используются для входа в информационную базу конфигурации «1С:УНФ 3.0» через платформу «1С:Предприятие»:

| Пользователь в «1С» | Назначенные права | Назначение при демонстрации |
|---|---|---|
| **Абдулов (директор)** | Администратор / Полные права | Демонстрация полного функционала: чат-панель ассистента, канбан-доска задач, создание задач, вызов интеграционных сервисов (пароль отсутствует) |
| **Абнагимова (продажи)** | Профиль «Продажи» + роль расширения «ИА_ИспользованиеАссистента» | Демонстрация ограниченного доступа сотрудника: интерфейс ассистента доступен, доступ к общим финансовым регистрам и чужим задачам ограничен RLS платформы (пароль отсутствует) |
| **Администратор** | Полные административные права | Служебный доступ для настройки прав и профилей БСП (пароль отсутствует) |

### 3.2. Контур внешнего интеграционного шлюза Middleware (REST API / Веб-портал)

Данные учётные записи используются исключительно для аутентификации во внешнем веб-портале (`http://127.0.0.1:8000`) и при обращениях к REST API. Они не вводятся в платформе 1С и предназначены для демонстрации ролевой модели безопасности Zero-Trust API Gateway: внешние клиенты лишены прямого подключения к базе 1С и проходят обязательную авторизацию по JWT-токенам на интеграционном шлюзе:

| Роль шлюза | Логин | Пароль | Разграничение полномочий шлюза |
|---|---|---|---|
| Генеральный директор | `director` | `director123` | Полный доступ: финансовые сводки, анализ кассовых разрывов, расчет маржинальности, согласование скидок |
| Финансовый директор | `cfo` | `cfo123` | Аналитика дебиторской задолженности, расчет неустоек (ст. 395 ГК РФ), комплаенс-контроль платежей (115-ФЗ) |
| Начальник склада | `warehouse` | `warehouse123` | Расчет складского баланса и точек перезаказа (ROP/EOQ), остатки номенклатуры |
| Менеджер по продажам | `manager` | `manager123` | Заказы покупателей, задачи своего подразделения, проверка надежности ИНН контрагентов |
| Линейный сотрудник | `employee` | `employee123` | Персональные задачи канбан-доски. Доступ к общим финансовым данным и кассовым разрывам блокируется (код 403 Forbidden) |

## 4. Порядок развёртывания программного комплекса в «1С:Предприятии 8»

### 4.1. Автоматизированное развёртывание в один клик (рекомендуемый способ)

Для обеспечения оперативного запуска экспертным жюри подготовлен сценарий полного автоматизированного развёртывания. Порядок запуска включает следующие шаги:
1. запустить командный файл `deploy_1c.bat` двойным щелчком мыши из корневого каталога проекта;
2. дождаться завершения автоматического поиска платформы 1С, регистрации информационной базы в списке `ibases.v8i` и восстановления структуры данных из файла `dist/SmallBusinessDemo.dt`;
3. подтвердить автоматический старт интеграционного шлюза `Middleware` на локальном порту 8000;
4. приступить к проверке в автоматически открытом сеансе приложения «1С:Предприятие 8» под пользователем «Абдулов (директор)».

### 4.2. Пошаговый ручной порядок развёртывания базы данных

При необходимости поэтапного контроля развёртывание выполняется штатными средствами платформы «1С:Предприятие»:
1. запустить стартер «1С:Предприятия», нажать кнопку «Добавить» $\to$ выбрать «Создание новой информационной базы» $\to$ «Создание информационной базы без конфигурации» и указать локальный каталог на накопителе;
2. выделить созданную базу в списке и нажать кнопку «Конфигуратор»;
3. в главном меню конфигуратора открыть «Администрирование» $\to$ «Загрузить информационную базу...», выбрать файл `dist/SmallBusinessDemo.dt` и подтвердить операцию загрузки;
4. после завершения загрузки запустить базу в режиме «1С:Предприятие» под пользователем «Абдулов (директор)» (пароль отсутствует);
5. в отдельном окне консоли запустить интеграционный сервер `Middleware` командой `.\Middleware\.venv\Scripts\python.exe Middleware\main.py`;
6. в интерфейсе «1С:УНФ 3.0» открыть раздел «ИИ Ассистент» и запустить рабочие места «Чат с ассистентом» и «Канбан-доска».

## 5. Сценарии демонстрации ключевых бизнес-модулей

### Сценарий 1: Нативная канбан-доска и диалоговый ассистент в «1С:Предприятии»

Порядок демонстрации включает следующие шаги:
1. открыть в интерфейсе «1С:УНФ 3.0» под пользователем «Абдулов (директор)» подсистему «ИИ Ассистент» $\to$ «Канбан-доска»;
2. проверить распределение задач по колонкам («К выполнению», «В работе», «На проверке», «Выполнено»);
3. нажать кнопку «Создать задачу» и проверить открытие нативной формы задачи 1С с привязкой к номенклатуре, контрагентам и заказам покупателей;
4. открыть форму «Чат с ассистентом» и ввести запрос на естественном языке (например: «Покажи остатки товара на складе»).

### Сценарий 2: Финансовый комплаенс и аудит контрагентов (115-ФЗ, ст. 54.1 НК РФ)

Порядок демонстрации включает следующие шаги:
1. перейти в веб-интерфейсе в раздел «Бизнес-инструменты РФ» $\to$ вкладка «115-ФЗ и Контрагенты»;
2. ввести тестовый ИНН контрагента (`7707083893`) и нажать кнопку «Проверить»;
3. оценить результаты валидации контрольных разрядов по модулю 11 и сопоставления реквизитов с признаками фирм-однодневок;
4. в блоке контроля платежей ввести сумму `650000` руб. с основанием платежа и проверить классификацию операции по пороговым критериям финансового мониторинга.

### Сценарий 3: Защита маржинальности сделок и контроль рентабельности

Порядок демонстрации включает следующие шаги:
1. открыть вкладку «Защита маржи»;
2. указать параметры сделки (себестоимость партии, запрашиваемая клиентом скидка, условия отсрочки платежа);
3. при снижении расчетной рентабельности ниже нормативного порога (15%) зафиксировать блокировку автоматического согласования и формирование задачи директору на канбан-доску для персонального акцепта.

### Сценарий 4: Расчет пени и формирование досудебных претензий (ст. 395 ГК РФ)

Порядок демонстрации включает следующие шаги:
1. открыть вкладку «Пени ст. 395 ГК РФ»;
2. указать сумму просроченного обязательства и период задержки оплаты;
3. нажать кнопку «Рассчитать проценты» и зафиксировать помесячный расчет штрафных санкций с учетом ключевых ставок Банка России;
4. нажать кнопку «Сформировать претензию» для генерации юридически корректного текста досудебного требования.

### Сценарий 5: Автоматизированный расчет складского баланса (модель Уилсона ROP/EOQ)

Порядок демонстрации включает следующие шаги:
1. открыть вкладку «Автозаказ ROP/EOQ»;
2. нажать кнопку «Рассчитать параметры заказа» и проверить расчет экономичного размера заказа (EOQ) и точки перезаказа (ROP) с учетом страхового запаса;
3. транслировать сформированные параметры в структуру документа «Заказ поставщику» конфигурации «1С:УНФ 3.0».

### Сценарий 6: Оптическое распознавание первичных документов (OCR)

Порядок демонстрации включает следующие шаги:
1. открыть вкладку «OCR счетов и УПД»;
2. загрузить файл или скан-образ счета на оплату;
3. проверить автоматическое сопоставление номенклатурных позиций поставщика со справочником «1С:УНФ 3.0» и верификацию ставки НДС 20%.

## 6. Завершение работы с демонстрационным стендом

Для корректной остановки демонстрационного сервера в окне консоли терминала нажать комбинацию клавиш `Ctrl + C`. Временные демонстрационные файлы автоматически очищаются.
