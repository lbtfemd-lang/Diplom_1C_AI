# 🌐 УНИВЕРСАЛЬНЫЙ ПРОТОКОЛ ПЕРЕДАЧИ КОНТЕКСТА (1С:ПРЕДПРИЯТИЕ + ВНЕШНИЙ ИИ-СЛОЙ)

Стандартизированный регламент фиксации и передачи состояния проекта для любых задач на стыке **«1С:Предприятие»**, **Middleware (Python / FastAPI)** и **языковых моделей (LLM / RAG / Action Dispatcher)**.

---

## 📋 ЧАСТЬ 1. ПРОМПТ ДЛЯ ПЕРЕДАЮЩЕГО АГЕНТА (OUTBOX)
> **Назначение:** Заставляет текущего агента собрать полную, структурированную выгрузку состояния архитектуры 1С, интеграционного шлюза и ИИ-модулей без привязки к конкретному сценарию.

```markdown
Твоя задача — сформировать ПОЛНЫЙ УНИВЕРСАЛЬНЫЙ ПАСПОРТ СОСТОЯНИЯ ПРОЕКТА (1С + ИИ-СЛОЙ) для бесшовной передачи контекста следующему агенту.

Сформируй структурированный отчет строго по следующим 7 разделам:

### 1. АРХИТЕКТУРА СИСТЕМЫ И ИНТЕГРАЦИОННЫЙ СТЕК
- Платформа 1С: версия платформы, режим запуска (Управляемое приложение / Веб-клиент), целевая конфигурация;
- Способ интеграции: внешние обработки (EPF/ERF), расширение конфигурации (CFE), HTTP-сервисы 1С или внешняя компонента;
- Внешний ИИ-слой (Middleware): фреймворк (FastAPI / Flask / Node.js), сетевой адрес и порт, способ авторизации (JWT / API Key), механизм тайм-аутов и ретраев;
- Провайдеры LLM: используемые модели, fallback-пул, локальные/облачные эмбеддинги для RAG.

### 2. СИСТЕМА НАВЫКОВ И ИНЖЕНЕРНЫЙ ИНСТРУМЕНТАРИЙ (.AGENTS/SKILLS)
- Реестр доступных навыков для 1С (сборка/разборка EPF, модификация форм, компиляция метаданных, генерация BSL-документации, аудит правил);
- Скрипты автоматизации: пайплайн сборки обработок, скрипты развертывания, фоновые демоны.

### 3. КАРТА КОДОВОЙ БАЗЫ И ЗОНЫ ОТВЕТСТВЕННОСТИ ФАЙЛОВ
- Модули 1С (клиентский UI, серверная бизнес-логика, монолитные BSL-исходники и XML-структура);
- Модули Middleware (маршрутизация намерений, валидация схем JSON, сервис метаданных, контроллеры API);
- Каталоги сборок, артефактов и логов.

### 4. МЕХАНИЗМЫ ВЗАИМОДЕЙСТВИЯ 1С И ИИ (ACTION DISPATCHER & UI)
- Паттерн обработки запросов: маршрутизация намерения (быстрый классификатор / LLM) -> JSON-схема действия -> вызов серверного метода 1С;
- Интерактивный UI: рендеринг карточек, Action Chips, обработка ссылок и команд, открытие объектов в 1С (платформенные методы `ПоказатьЗначение`);
- Обработка ошибок: валидация ответов нейросети, логирование исключений 1С, вывод понятных сообщений пользователю.

### 5. ТЕХНИЧЕСКИЕ ОСОБЕННОСТИ И РЕШЕНИЯ ДЕБАГА (1C METADATA QUIRKS)
- Особенности целевой конфигурации 1С (структура регистров, обязательные реквизиты документов, специфика поиска объектов);
- Контекстное разделение методов 1С (&НаКлиенте, &НаСервере, &НаСервереБезКонтекста);
- Устраненные критические ошибки и принятые архитектурные решения.

### 6. ТЕКУЩЕЕ СОСТОЯНИЕ, ПРАВИЛА И СЛЕДУЮЩИЕ ШАГИ
- Текущий приоритет работы (практическая разработка и дебаг кода / тестирование / документация);
- Правила проекта (академический/корпоративный стиль, кавычки «», оформление списков, запрет лишних терминальных команд);
- Четкий пошаговый план ближайших действий.

### 7. ВХОДНОЙ ПРОМПТ ДЛЯ ПРИНИМАЮЩЕГО АГЕНТА
- Готовый блок текста для быстрой инициализации следующего агента.
```

## 📥 ЧАСТЬ 2. ПРОМПТ ДЛЯ ПРИНИМАЮЩЕГО АГЕНТА (INBOX)
> **Назначение:** Отправляется новому агенту в начале сессии вместе со сформированным отчетом из Части 1.

```markdown
Ты вступаешь в проект в роли ведущего разработчика 1С:Предприятие и AI-инженера (Python / Middleware).

Изучи переданный паспорт состояния проекта и файлы в рабочей директории.
Для подтверждения приема контекста сформируй структурированный ответ:
1. Подтверди понимание архитектуры (1С + Middleware + LLM-слой) и текущего приоритета работы.
2. Подтверди готовность использовать инженерные навыки из `.agents/skills/` (включая компиляцию, инспекцию форм и валидацию метаданных 1С).
3. Опиши свое понимание текущего статуса функционала и ключевых особенностей метаданных 1С.
4. Сформулируй свой первый конкретный шаг, к которому ты готов приступить немедленно.
```
