# 🌐 УНИВЕРСАЛЬНЫЙ ПРОТОКОЛ ПОЛНОЙ СУММАРИЗАЦИИ И ПЕРЕДАЧИ КОНТЕКСТА (UNIVERSAL SESSION HANDOVER PROTOCOL)

Этот документ представляет собой **стандартизированный регламент и шаблон мастер-промпта**, который заставляет любого ИИ-агента (в Antigravity 2.0, Antigravity IDE, Claude/GPT или другой среде) сформировать 100% полную, структурированную и безошибочную выгрузку состояния проекта для следующего агента.

---

## ЧАСТЬ 1. ПРОМПТ ДЛЯ АГЕНТА: «СГЕНЕРИРУЙ ПОЛНЫЙ ОТЧЕТ ПЕРЕДАЧИ КОНТЕКСТА»
> **Кому отправлять:** Текущему работающему агенту, когда нужно зафиксировать этап, подвести итоги и подготовить полную сводку для следующего агента/сессии.

```markdown
Твоя задача — выполнить процедуру ПОЛНОЙ СУММАРИЗАЦИИ И ФИКСАЦИИ СОСТОЯНИЯ ПРОЕКТА (Full State Handover) по стандартизированному протоколу.

Сформируй исчерпывающий отчет передачи контекста строго по следующим 8 обязательным разделам:

### 1. ПАСПОРТ ПРОЕКТА И СТЕК ТЕХНОЛОГИЙ
- Название и цель дипломного проекта;
- Версии и окружение: версия платформы 1С (8.5.1.1302 / 8.3), конфигурация («1С:УНФ 3.0»), версия Python (3.12), фреймворк бэкенда (FastAPI), используемые LLM-провайдеры (Google Gemini / OpenRouter / Groq);
- Рабочая директория, используемые локальные порты (8000), фоновые службы.

### 2. ПРАВИЛА И ОГРАНИЧЕНИЯ ПРОЕКТА (GOVERNANCE RULES)
- Академические стандарты оформления текста диплома: кавычки «», оформление списков с маленькой буквы и точкой с запятой (;), оформление ссылок на рисунки (рисунок 3.X), обязательный текст после таблиц/рисунков, отсутствие личных местоимений;
- Правила работы с кодом: запрет на терминальные команды в диалогах с пользователем (если не запрошено), использование только реальных объектов метаданных 1С:УНФ, русский язык коммуникации.

### 3. РЕЕСТР АКТИВНЫХ НАВЫКОВ (SKILLS & TOOLS REGISTRY)
- Список ключевых задействованных навыков из `.agents/skills/` (сборка `epf-build`/`epf-dump`, работа с формами `form-compile`/`form-edit`, валидация `action-dispatch-validate`/`bsl-doc-gen`/`diploma-audit`);
- Вспомогательные скрипты сборки и синхронизации (`scratch/compile_epfs.py`, `copy_to_desktop.py`).

### 4. КАРТА КОДОВОЙ БАЗЫ И ФАЙЛОВАЯ СТРУКТУРА
- Точные абсолютные и относительные пути ко всем ключевым файлам:
  * Монолитные и декомпилированные BSL-модули чата и канбан-доски;
  * Исходники FastAPI Middleware (`main.py`, `llm_service.py`, `metadata_service.py`, `api_models.py`);
  * Готовые сборки обработок на Рабочем столе и в `1c_extensions/build/`.

### 5. ДЕТАЛЬНЫЙ СТАТУС 5 БИЗНЕС-СЦЕНАРИЕВ АВТОМАТИЗАЦИИ
По каждому из 5 сценариев укажи:
  1. Название и action ID (например, `parse_order_text`, `generate_debt_letters`, `create_procurement_order`, `generate_commercial_proposal`, `audit_stalled_orders`);
  2. Точный пример пользовательского запроса;
  3. Алгоритм обработки (какие регистры 1С опрашиваются, как рассчитываются данные, какие документы создаются);
  4. Текущий статус готовности и результаты тестов в 1С.

### 6. ИСТОРИЯ ДЕБАГА И КРИТИЧЕСКИЕ ТЕХНИЧЕСКИЕ РЕШЕНИЯ (EDGE CASES)
- Особенности структуры 1С:УНФ (отсутствие реквизита `ОсновнойДоговорКонтрагента` -> запрос к `Справочник.ДоговорыКонтрагентов`);
- Обязательные реквизиты документов («Заказ покупателя», «Заказ поставщику»: `СостояниеЗаказа`, `ВалютаДокумента`, `ПоложениеСклада = ВШапке`, `НалогообложениеНДС`);
- Архитектура навигации по ссылкам: замена устаревших `ОткрытьФорму` на платформенный метод `ПоказатьЗначение(, Ссылка)`, безопасный парсер параметров `ШПолучитьПараметр`;
- Быстрый классификатор намерений `_fast_classify_intent` (<10 мс) и классовый `VALID_ACTIONS`.

### 7. ТЕКУЩЕЕ СОСТОЯНИЕ И НЕПОСРЕДСТВЕННЫЙ ФОКУС (WHAT TO DO NEXT)
- Какая задача решается прямо сейчас;
- Что конкретно должен протестировать или сделать пользователь в 1С;
- Что ожидает система от следующего шага.

### 8. ГОТОВЫЙ ВХОДНОЙ ПРОМПТ ДЛЯ СЛЕДУЮЩЕГО АГЕНТА (INCOMING AGENT PROMPT)
- Компактный, емкий блок для копирования новому агенту, чтобы тот мгновенно вошел в курс дела и подтвердил готовность по чек-листу.
```

## ЧАСТЬ 2. ПРОМПТ ДЛЯ ПРИНИМАЮЩЕГО АГЕНТА: «ПРИМИ КОНТЕКСТ И ПОДТВЕРДИ ГОТОВНОСТЬ»
> **Кому отправлять:** Новому агенту в новой сессии/IDE вместе с отчетом, полученным из Части 1.

```markdown
Ты вступаешь в проект в роли ведущего разработчика 1С и Python / AI Architect.
Внимательно изучи переданный отчет состояния (Handover Protocol) и файлы в рабочей области.

Для подтверждения приема контекста сформируй структурированный ответ:
1. Подтверди текущий приоритет (практическая отладка/тестирование 1С, а не текст диплома).
2. Подтверди понимание архитектуры (FastAPI :8000, 1С:УНФ 3.0, монолитные BSL и EPF).
3. Опиши готовность 5 сценариев автоматизации и статус интерактивных кнопок чата.
4. Укажи первый шаг, который ты готов выполнить прямо сейчас.
```
